# Viora Manager v1.4.5 — Roblox OAuth identity linking (development)

## Why this change is necessary

The older **+ Add an Account** created a browser-owned profile and opened a normal Roblox login page. **Signing in on that page never notified Viora of the username or Roblox User ID.** That is expected: the browser's Roblox login cookies are intentionally inaccessible to the Manager. Merely seeing a Roblox page does not prove that the Player is using that account.

v1.4.5 adds explicit, official **Roblox Open Cloud OAuth 2.0 authorization-code + PKCE** to verify the signed-in user's *identity*, without collecting login cookies or passwords.

## One-time Roblox OAuth application registration (developer preview)

1. Go to [Roblox Creator Dashboard → Credentials](https://create.roblox.com/dashboard/credentials). Create an **OAuth 2.0 application**.
2. Configure only the identity scopes **`openid`** and **`profile`**. No permission to modify accounts, games, messages or currency is needed.
3. Register the **exact callback/redirect URL**: `http://localhost:39141/oauth/callback/` (including the trailing slash).
4. Copy your application's **Client ID** (a public, numeric identifier), *not the Client Secret*.
5. In Viora Manager, open **+ Add an Account** or **Edit**, expand **One-time setup: official Roblox OAuth Client ID**, enter the ID and click **Save Client ID**.
6. If port 39141 is occupied or Windows denies the local callback listener, OAuth will show an error. Viora does not use global firewall changes to bypass this.

**For a future public Manager release:** the project maintainer should register and configure the application's Client ID for the build, rather than expecting each user to create their own OAuth application. The Roblox app may require review or quota setup before a larger audience can connect. The current preview has a local Client ID field for developer testing and doesn't bundle one.

## Using it

- With a Client ID saved, **+ Add an Account** creates the local browser profile, opens Roblox's **official OAuth authorisation/consent screen** in that profile and waits for the local callback.
- Sign into Roblox if needed, and approve Viora's request for basic identity (openid/profile).
- After Roblox sends the callback, Viora exchanges a one-time code using **PKCE**, calls Roblox's `/oauth/v1/userinfo`, and stores the verified Roblox **User ID**, **username**, and **public display name**.
- An autogenerated `Account1` label is replaced by the Roblox username unless it conflicts with an existing saved label. Existing custom nicknames stay unchanged.
- Accounts Home displays a **✓ OAuth linked** indicator for the matched Roblox User ID. The avatar remains fetched from Roblox's separate public thumbnail API; it isn't scraped from browser cookies.
- Existing accounts: select one in Edit and press **✓ Connect verified Roblox account**.
- Without a Client ID, + Add an Account **still opens a Roblox browser login**, but the status explicitly explains that Viora **cannot detect the identity** until official OAuth is configured. Public username lookup and manual nicknames remain available.

## Security boundaries

- Request only `openid profile`, require a randomly generated state and PKCE S256 verifier/challenge, and use a short-lived localhost callback.
- No OAuth refresh/access token, Roblox password, MFA code, Roblox authentication ticket, or `.ROBLOSECURITY` cookie is saved to disk or the project repository.
- The local account JSON records only non-secret identity metadata: `VerifiedRobloxUserId`, `VerifiedAtUtc`, public profile details, nickname and browser profile GUID.
- The callback is local-only at `localhost:39141`; the same exact URL must be allow-listed in Roblox OAuth app settings.
- **Important:** OAuth confirms that the user authorised Viora as a particular Roblox identity *at that time*. It **does not authenticate Roblox Player** or guarantee that Play opens a desktop client as the same account. Browser cookies are managed separately by Edge/Chrome/Brave, not by Viora.
- The v1.4.5 preview is for development testing and does not resolve the existing VirusTotal false-positive investigation. Don't tell users to disable antivirus.

## What to test on a real Windows computer

- [ ] v1.4.5 standalone Windows x64 executable builds in GitHub Actions.
- [ ] Register developer OAuth app with the specified exact localhost redirect and openid/profile scopes.
- [ ] Paste the public Client ID in Viora, verify it persists after restart.
- [ ] Add Account opens a Roblox sign-in/consent screen, authorisation returns to Manager without manual username copying.
- [ ] Username, User ID and public display name appear after consent; pressing Refresh profiles populates avatar.
- [ ] Add two different accounts in separate browser profiles; verify distinct IDs/names and preservation across restarts.
- [ ] Existing unverified `Account1` can be upgraded by selecting it and pressing Connect verified Roblox account.
- [ ] OAuth cancellation, declined consent, invalid redirect, incorrect Client ID, wrong browser, busy port, timeout and network failure produce useful messages without overwriting account details.
- [ ] Existing manually entered nicknames are preserved. A duplicate linked identity is rejected.
- [ ] Accounts-first UI and Instances & Tools still work, and no browser cookies or OAuth tokens are stored by Manager.
- [ ] Explicitly test Play separately: identity linking **must not** be confused with automated desktop Player authentication.
