# Viora v1.4 acceptance checks — Game Workspaces Lite

**Status:** development preview; do not merge, tag, or post in #updates until these checks pass on Windows. Base: v1.3 release-candidate branch. Viora Manager behaviour/UI must remain the original.

## 1. Before testing

- Use a backed-up Windows user account with real Roblox installation; capture Windows version, DPI scaling, and Viora version.
- Copy `%LOCALAPPDATA%\Viora\settings.json` to a safe place.
- Build the official full + Lite Windows packages with GitHub Actions and verify output `.sha256` files. Validate a clean build and that main-launcher and Manager build outputs both exist.
- Run from a fresh settings file and from an existing v1.3 settings file (do not delete/migrate saved shortcuts).

## 2. Workspaces & old settings

- With no saved shortcuts, verify **All workspaces** and **0 shown / 0 workspaces**, no crash.
- Save games into separate workspace names (for example `Simulators` and `Obbies`). Confirm switching workspace filters only visible shortcuts, not data.
- Search within a workspace by game name, folder, and place ID; switching back to **All workspaces** restores the full list.
- Edit a shortcut's name, place ID, workspace, FPS, graphics, and FastFlag assignment; ensure it is displayed in its new workspace and retains its profile.
- Rename a workspace with several games. Verify all affected shortcuts move while keeping their place IDs and performance assignments.
- Rename into an existing workspace and reject/accept the merge confirmation; verify neither action deletes games.
- Remove the final game in a workspace; confirm the selector falls back to **All workspaces** without an exception.
- Restart Viora and confirm workspace grouping and assignments persist through existing `LaunchShortcuts` settings. Confirm v1.3 backups remain intact.
- Confirm the special `All workspaces` label cannot be saved as a workspace name.

## 3. Launch & safety

- From each workspace, open a saved shortcut with **no** performance assignment and verify the official roblox.com URL opens.
- Configure a profile and graphics settings; while Roblox is running, verify Viora refuses to apply them and closes/disposes observation process handles.
- With Roblox closed, verify the existing confirmation, application and launch flow. Verify actual Roblox honours only supported settings; Viora must not claim unsupported flags are active.
- Confirm removed Game Hub favourites do not return, and **Viora Manager** retains the original interface and experimental toggle behaviour.

## 4. Performance and reliability

- On the same Windows device, compare v1.3 vs v1.4: idle launcher CPU/RAM (5 min), Quick Launcher typing latency, Game Hub typing latency, tab switching and 30 min session stability. Repeat at least 3 times under similar conditions and record measurements; don't claim a speedup unless measured.
- Populate enough Game Hub entries to exercise scrolling and artwork. Confirm only visible-page artwork starts loading and no off-screen chart rebuilding causes freezes or stale values upon navigation.
- Rename/reconfigure shortcuts while searching and switching pages, and check that no reentrant WPF events cause a crash.
- Intentionally corrupt a **copy** of the settings file. Launch, attempt to save, and verify the original malformed file is preserved unchanged. Restore the backed-up settings afterwards.
- Check common scaling modes (100%, 125%, 150%) and keyboard navigation; ensure the new toolbar stays readable without horizontal clipping.

## 5. Packaging and release gates

- Validate Lite package on a machine with .NET Desktop Runtime 8 x64 and full installer on one without it.
- Exercise launcher-only and launcher + original Manager install/update. Compare Manager source/UI against v1.3; only version metadata should differ.
- Verify hash mismatch, update refusal while Manager is active, rollback to `.previous`, and staged-file cleanup.
- Gather a pass/fail record (Windows build logs, screenshots, timings, bugs). Only then approve the PR, merge in the intended order after v1.3 and consider a signed/tagged release.
